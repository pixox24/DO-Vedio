# 输入式首页：方案

> 日期：2026-10-10
> 范围：`/` 首页、`/projects` 列表页、顶栏导航
> 底线：新建项目的行为与结果不变（同一个接口、同一套默认制作预设）；项目列表的全部既有能力不退化；键盘可达与 `prefers-reduced-motion` 一并处理。

---

## 一、目标

把「新建项目」从一个弹窗（`components/project-list.tsx:199`）升级成一个**独立首页**：
形态参照主流大模型平台的入口——一个居中、固定多行的输入框，内嵌模式下拉与发送按钮，
回车即提交。输入框承载三种模式的入口，其中只有第一个是已实现的能力，另两个是占位。

### 1.1 三个模式

| 模式 | 状态 | 输入语义 | 提交行为 |
|---|---|---|---|
| ① 输入标题 | **已实现** | 视频标题 | 组装 `emptyDoc()` + `brief.title` → `POST /api/projects` → `router.push('/projects/{id}')` |
| ② 输入已有文案 | 占位 | 粘贴写好的整篇文案 | 可输入；提交时 toast「该功能开发中」 |
| ③ 分析爆款 | 占位 | 一个选题 | 同上 |

模式②的将来形态是「贴成品文案 → 跳过写稿，直接进入断句标注 / 配音 / 分镜」；
模式③是「输入选题，反推同类爆款的钩子、结构与标题套路」。两者的 placeholder 与说明文案按此方向写，
以免将来做的时候文案与实际能力对不上。

### 1.2 为什么放在同一个输入框里

三个模式的用户动作在形态上是同一个：**把一段文字交出去**。区别只在「这段文字被如何理解」。
所以共用一个输入框、把差异收进模式选择，比做三个独立入口更轻，也与「大模型平台入口」的心智一致。

## 二、现状（改动前）

### 2.1 涉及的文件

| 文件 | 现状 |
|---|---|
| `app/page.tsx` | 只有 5 行，直接渲染 `<ProjectList />` |
| `components/project-list.tsx` | 首页的全部内容：新建弹窗、旧草稿导入条、搜索、排序、卡片网格、删除、复制 |
| `components/project-list.tsx:121-123` | 「新建项目」按钮 → `setCreateOpen(true)` |
| `components/project-list.tsx:199-222` | `Dialog` + 单个 `input` + `createFromTitle()` |
| `components/project-list.tsx:67-78` | `create()`：POST `/api/projects`，成功 `router.push`，失败把错误留在 `error` state |
| `app/api/projects/route.ts:22-34` | 不传 `presetId` 时自动套用**默认制作预设** |

### 2.2 必须保持的行为

1. 新建时服务端自动套用默认制作预设（`app/api/projects/route.ts` 的 `presetId === undefined` 分支）。
   首页只要继续走同一个接口，这条能力天然保留，**首页不需要感知预设**。
2. 创建失败时错误必须可见，且允许重试（现在渲染在弹窗底部；新形态改为渲染在输入框下方）。
3. `Enter` 提交。
4. 旧草稿导入条（`do-vedio:draft`）继续工作——它是「导入」而不是「新建」，留在列表页。

## 三、路由与结构

| 路由 | 内容 |
|---|---|
| `/` | **只有输入区**。垂直居中的输入框 + 模式下拉 + 发送按钮 + 示例 chips + 缓动光晕背景 |
| `/projects` | **新建**。现有项目列表整页平移过来 |
| `/projects/[id]` | 不变 |

### 3.1 改动清单

- `app/page.tsx`：改为渲染新组件 `components/home-composer.tsx`（不再渲染 `ProjectList`）。
- 新增 `app/projects/page.tsx`：渲染 `<ProjectList />`。
- 新增 `components/home-composer.tsx`：首页输入区，含 `create()`（从 `project-list.tsx` 迁来）。
- `components/project-list.tsx`：
  - 删除新建 `Dialog`、`createOpen` / `createTitle` 两个 state、`createFromTitle()`；
  - 保留 `create()` 的服务端调用逻辑（迁到首页），列表页不再需要它；
  - 顶部「新建项目」按钮（`:121-123`）改为 `Link href="/?focus=1"`，点击回首页并聚焦输入框。
- `components/nav.tsx`：`项目` 的 `href` 由 `/` 改为 `/projects`（`:70`），`projectsActive` 判定（`:66`）同步调整，
  使 `/projects` 与 `/projects/[id]` 都算选中，而 `/`（首页）不算。

**Logo 仍指向 `/`**（回首页），这是首页作为入口的必要条件。

### 3.2 关于 `/` 的取舍

首页只有输入区，意味着**回访老项目多了一步**：得经顶栏进 `/projects`。
这是用户明确选择的结果（「首页只有输入区」）。为避免这一步的成本过高，模式下拉里会带一个
「我的项目 →」的次级出口（见 §4.3）。

## 四、输入区设计

### 4.1 形态

固定多行的多行框，约 4 行高起，超出后在框内滚动（复用 `components/ui.tsx` 的 `AutoTextarea` 思路）。
结构自上而下：

```
┌──────────────────────────────────────┐
│  为什么年轻人开始逃离大城市？        │  ← textarea，固定 4 行起
│                                      │
│                                      │
│                                      │
│  ╭─────────╮                 ╭───╮  │
│  │ 标题  ▾ │                 │ ↑ │  │  ← 底部：模式触发器 + 发送
│  ╰─────────╯                 ╰───╯  │
└──────────────────────────────────────┘
  回车创建 · Shift+回车换行              ← 辅助小字（随模式变化）
```

- 发送按钮为圆形，accent 底色 + 黑箭头，空输入时禁用（`disabled:opacity-35` 沿用 `.btn` 既有规则）。
- 提交中按钮内换成 `<Spinner />`，**按钮尺寸不变**（避免布局跳动）。
- 错误信息渲染在输入框正下方，用 `Alert tone="danger"`。

### 4.2 模式下拉

触发器是一个紧凑 pill：当前模式图标 + 名称 + chevron。展开后是一个浮层菜单，列三项，
选中项由**共享滑块**滑动指示（滑块 `transform: translateY()` 到当前项，弹簧曲线）。

- 定位与键盘逻辑**参照** `components/ui.tsx` 里 `Select` 已实现的那套（`:319-400`）：
  `getBoundingClientRect` 计算位置、上下翻页避让、`ArrowUp/Down` 移动、`Enter` 选中、`Esc` 收起并回焦、点外收起。
- 三项的图标复用现有 `Icon`（`components/ui.tsx:545-577`），**不新增图标资源**：
  ① `text` ② `copy` ③ `bolt`。
- 菜单**默认收起**。需求里的「默认就是第一个功能」理解为「默认**选中**第一项」，不是「默认摊开菜单」——
  摊开会盖住输入框。

### 4.3 菜单内的次级出口

菜单底部加一行分隔线 + 「我的项目 →」，指向 `/projects`。理由见 §3.2。

### 4.4 三态的 placeholder 与辅助小字

| 模式 | placeholder | 辅助小字 |
|---|---|---|
| ① 输入标题 | 例如：为什么年轻人开始逃离大城市？ | 回车创建 · Shift+回车换行 |
| ② 输入已有文案 | 粘贴你已经写好的文案，直接进入断句标注与配音 | 回车换行 · ⌘/Ctrl+回车提交 |
| ③ 分析爆款 | 输入一个选题，反推同类爆款的钩子、结构与标题套路 | 回车换行 · ⌘/Ctrl+回车提交 |

### 4.5 键盘契约

- 模式①（标题不含换行）：`Enter` 直接提交，`Shift+Enter` 不参与。
- 模式②③：`Enter` 换行，`⌘/Ctrl + Enter` 提交。
- `Esc` 收起菜单。
- 从 `/projects` 的「新建项目」跳回时（`/?focus=1`），输入框自动聚焦。

> 实现注记：带 `?focus=1` 的客户端组件若用 `useSearchParams()`，Next 要求外层有 `<Suspense>` 边界，
> 否则整页转 CSR。落地时按 `node_modules/next/dist/docs/` 的 App Router 指南确认写法。

### 4.6 氛围元素

1. **示例提示 chips**：输入框下方一排可点示例，点击填入输入框（填入时输入框边框提亮一瞬）。
   示例**按模式不同**，切模式时交叉淡入。
2. **缓动光晕背景**：一层极慢速的 accent 径向渐变，跟随鼠标微幅偏移。
   用 `transform: translate3d()`，只走合成层，不触发重排。
   强度**克制**在 accent 的 3%–6% 透明度——页头 `body` 已经有一层静态渐变
   （`app/globals.css:191-196`），这层只是让它活起来，不是叠一层新的重光。
3. **模式说明小字**：即 §4.4 的辅助小字。模式①下它会写明「其余交给默认预设」，让自动套用预设这件事可见。

### 4.7 与既有设计系统的关系

- 颜色 / 圆角 / 字号**全部**走 `app/globals.css` 的 `@theme` 令牌，不新造 hex 与透明度魔数
  （`components/ui.tsx:19-25` 写明的项目约定）。
- 复用 `.input` / `.panel` / `.chip` / `.btn` / `.select-menu` 等语义类。
- 新增的动效 keyframes 加进 `@theme` 的 `--animate-*`，并**同时**加进 `app/globals.css:443` 的
  `prefers-reduced-motion` 关停清单——这是现有约定（该清单会逐一列举每个动画）。
- 动画曲线沿用仓库现有的 `cubic-bezier(0.2, 0.8, 0.2, 1)` 家族。

## 五、动效清单

「丝滑」不是形容词，是下面这五条可验收的具体行为：

| # | 时机 | 行为 |
|---|---|---|
| 1 | 首屏入场 | 输入框 → 示例 chips → 辅助小字**依次**淡入上浮，间隔错开；不是整块一起出现 |
| 2 | 模式切换 | 菜单滑块弹簧位移；placeholder 与辅助小字**交叉淡入淡出 + 轻微上移**，不是硬切 |
| 3 | 示例 chip 点击 | 文本填入输入框；输入框边框提亮一瞬（复用 `generation-breathe` 的思路） |
| 4 | 提交中 | 发送按钮内箭头 → `Spinner`，**按钮尺寸不变** |
| 5 | 常驻 | 背景光晕极慢速漂移，跟随鼠标微幅偏移 |

## 六、边界与失败态

| 情况 | 处理 |
|---|---|
| 标题为空 | 发送按钮禁用；不提交 |
| 创建请求失败 | 错误渲染在输入框下方（`Alert tone="danger"`），保持可重试，输入内容不丢 |
| 创建请求进行中 | 按钮 loading，输入框与模式下拉一并禁用，避免重复提交 |
| 模式②③ 提交 | `useFeedback().toast("该功能开发中", "info")`；不发起请求，不清空输入 |
| 减弱动效 | 所有新增动画在 `@media (prefers-reduced-motion: reduce)` 下关停；光晕静态化 |

## 八、验收

- 首页输入标题回车 → 创建成功并进入 `/projects/{id}`，与旧弹窗行为一致。
- 新建的项目带上默认制作预设（在项目里检查字幕 / 音色 / 画幅 / 风格是否已按预设配好）。
- `/projects` 保留：网格、搜索、排序、删除入回收站、复制、旧草稿导入条。
- 顶栏「项目」在 `/projects` 与 `/projects/[id]` 下高亮，在 `/` 下不高亮。
- 模式②③ 可切换、可输入，提交后出「开发中」提示且输入不清空。
- 全键盘可用：Tab 可达、方向键选模式、Esc 收菜单、⌘/Ctrl+回车提交。
- 系统开启「减弱动效」后，首页无位移 / 缩放 / 无限循环动画。
- `npm run typecheck`、`npm run lint` 通过；`/changelog` 正常渲染。

## 九、不做的事

以下都**不在本次范围**，避免方案膨胀：

- 不实现模式②③ 的真实功能（本次只做入口与形态）。
- 不做多步确认区（提交后不再展开「解说风格 / 目标时长」第二屏）——保持一步到位。
- 不改新建接口、不改默认预设的套用逻辑。
- 不把模式写进 URL（纯组件状态，刷新回默认「输入标题」）。
- 不做三个模式各自独立的路由。
