# 重点文字动效系统执行指南

## 目标与边界

画面表达只区分“生成画面”和“重点文字”。单字、词组、数字、关键句和观点共用一种内容结构；章节、金句、对比、数据、列表等不再决定新镜头的视觉模板。已有的两批 18 张静态排版探索保留为备选方向，不改动源图和评审 composition。

重点文字用于观点落点、关键数字、认知转折。默认不连续出现两张；真实场景和叙事动作仍用生成画面。文字是画面的主角，装饰符号、细线、低对比底纹只提供秩序和节奏。

## 数据契约

`Shot.focusText` 是新镜头唯一的文字画面输入：

```ts
type FocusText = {
  text: string;                    // 视觉核心，最多 8 个等价汉字宽度
  emphasis?: string;               // text 中需要强调的连续片段
  support?: string;                // 可选小字，最多 8 个等价汉字宽度
  layoutMode?: "auto" | "shuffle" | "manual";
  presetId?: FocusPresetId;        // 只在 manual 下生效
};
```

生成模型负责**语义提炼**，不允许机械截取前 8 字。生成结构校验拒绝超长文字，让生成过程重新尝试；草稿转换遇到异常内容时，优先采用已有完整关键词或短语。没有可辨识内容时不把截断当成总结。人工输入保留完整原文，在编辑区和时间轴提示超长；预览收缩字号，需人工概括后再交付。数字不得编造，尤其是百分比和倍数必须出自旁白。`card`、旧 `kind=title/quote` 和旧模板 ID 只作为历史项目的读取兼容字段，新分镜不再产出。

## 排版与动效匹配

两批静态设计转成 18 个 `FocusPreset`。它们是视觉排版方案，不是内容类型。每个方案声明适用的视觉宽度范围、主字位置与字体、强调方式、符号、底纹和动画节奏。筛选先看等价视觉宽度，再看数字/文字结构；横竖屏共用语义但分别计算可用宽度。

| 内容宽度 | 优先构图 | 入场 |
| --- | --- | --- |
| 1–2 | 单字放大、偏心、空实叠字 | 虚焦渐清晰或蒙版 |
| 3–4 | 紧凑字组、交叉符号、宋黑对照 | 整体渐现或分组错峰 |
| 5–6 | 错位两组、大字与小字 | 蒙版揭示或轻微升起 |
| 7–8 | 舒展单行、分栏、有限的辅助字 | 分组渐现或短打字机 |
| 数字 | 大数字与低调单位、标签 | 从 0 递增，标签升起渐现 |

自动模式按适配度选方案，并降低最近用过的版式、同位置、同符号的权重；同分候选用镜头 seed 决定，确保预览和成片一致。随机探索只在适配的方案中变换。手动模式允许锁定方案；文字变化导致不适配时仍优先保证画面不溢出。一条视频固定一组低饱和点缀色，排版变化不应使视觉主题跳色。

主字、辅助字、符号错峰入场，退场统一淡出。打字机只给适合逐步阅读的短句；单字和短词整体揭示。百分比、倍数从 0 递增；年份、电话号码和句子中的序号保持原值。全部动效只使用 Remotion 逐帧值，不使用 CSS transition/animation。字幕安全区按实际位置、字号与双语配置计算；横竖屏共用方案选择，独立计算尺寸。竖排方案遇到数字或长句回退到横排。

## 生产链路

1. 分镜提示词只输出 `focusText`，镜头类型仍兼容既有持久化枚举，但新生成的文字镜头统一使用 `kind=placeholder, mode=motion`。
2. 清洗 `focusText`，从旧 `card/onScreenText` 映射历史内容。旧卡片的多字段只能选最重要的一个核心；数字优先数值，其他优先可辨识的关键词。
3. 时间轴为文字镜头选择确定性的排版 preset 和动效方式。邻接抑制只处理新生成镜头，手动锁定内容不强制改写。
4. 渲染器使用统一的重点文字画面，不按旧卡片类型分支。旧模板文件与标识符改为 `legacy` 命名；历史 ID 字符串保留供项目文件读取。
5. 分镜面板提供核心文字、可选强调/辅助文字、智能/探索/手动排版。模板目录只展示排版方案，不再展示“数据卡/问答卡”等业务分类。

## 验收

- 新分镜不出现 `card` 分类及新 `title/quote` 文字镜头；相邻重点文字尽量交替为生成画面。
- 重点文字不超过 8 个等价汉字宽度，数字与 `%` 可按实际视觉宽度计；人工编辑长文本时有明确提示。
- 同一项目的预览与成片选中相同方案；相邻文字镜头的方案不连续重复；随机探索随 seed 固定。
- 横屏、竖屏的 1 字、4 字、8 字、百分比都不溢出字幕安全区，数字动画在中段可见且尾段淡出。
- 旧项目仍可加载并转为重点文字展示，旧模板 ID 不导致解析失败；两批静态评审稿保持不变。
- `npm run typecheck`、`npm run lint`、相关测试与 Remotion 关键帧渲染通过，`/changelog` 正常显示本次版本记录。

## 落地文件与复现

| 环节 | 文件 | 职责 |
| --- | --- | --- |
| 契约与提炼 | `lib/core/types.ts`、`lib/prompts.ts`、`lib/pipeline/stages/storyboard.ts` | 只生成统一重点文字，校验字宽、原文数字，保留旧草稿转换入口 |
| 镜头节奏 | `lib/core/shots.ts` | 本轮可编辑镜头交替，保护锁定和局部重做之外的镜头 |
| 匹配 | `lib/core/focus.ts`、`lib/core/timeline.ts` | 完整短语清洗、旧卡转换、宽度筛选、最近方案抑制、确定性 seed |
| 渲染 | `remotion/animation/focus-text.tsx`、`remotion/video.tsx` | 18 份排版参数、大小字与符号、逐帧动效、字幕避让 |
| 编辑 | `components/studio/storyboard-panel.tsx` | 核心文字、辅助字、强调、手动锁定及“换一个排版” |
| 历史兼容 | `lib/core/legacy-templates.ts`、`remotion/animation/legacy-templates.tsx` | 生产文件和符号迁名；历史模板 ID 不变，历史来源记录保留真实名称 |

新项目直接采用新规则。已有项目打开预览时从原字段派生重点文字，无需重写原始项目文件；需要重新渲染才能得到新版成片。重新生成分镜时新数据只保存 `focusText`，分镜缓存契约版本为 4。

```sh
node --import tsx scripts/focus-text-probe.ts
```
