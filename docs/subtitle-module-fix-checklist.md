# 字幕模块修复清单

> 状态：待执行
>
> 来源：字幕模块只读审查。当前字幕专项测试 12 项通过，但没有覆盖本清单列出的主要边界。
>
> 目标：字幕不丢字、时间不串行、翻译不覆盖用户编辑；所有可调样式在预览和导出中表现一致，设置含义清晰且可访问。

## 执行原则

- 开始前先检查 `git status`，在当前工作区已有改动上继续工作，不回滚、不覆盖无关改动。
- 每个工作包先补回归测试，再修实现。测试应复现用户可见的问题，而不是只断言内部函数调用。
- 一个工作包只修改其分配的文件。若发现必须扩大文件范围，先在任务说明中指出冲突和原因。
- 修复翻译时只允许把译文字段合并回当前项目文档；不得把请求开始时的整份句子快照写回。
- 重大体验修复完成后，按根目录 `AGENTS.md` 更新 `lib/changelog.ts`，运行 `npm run typecheck`、`npm run lint`，并确认 `/changelog` 正常渲染。

## 跨工作包不变量

- **译文新鲜状态唯一**：只有非空译文、目标语言正确、`secondaryHash` 存在且等于当前主行哈希时，才算 fresh。覆盖率、待翻译队列和实际渲染共用这一判定；没有哈希的兼容旧数据不得计入 fresh，也不得静默伪装成已验证译文。
- **异步结果按行合并**：请求携带 `lineId + primaryHash`。响应只包含翻译字段；提交时在最新文档上查找相同行 ID，并再次确认主行哈希未变。删除行跳过，新增行保留，源文已改的行丢弃旧译文；绝不整体替换请求开始时的 `lines`。
- **语言方向按单位确定**：默认对每句识别源语言，按语言分组或把源语言随每个单位传递。低置信度文本不猜方向；显式统一语言模式可以覆盖自动识别，但服务端质量检查使用该句实际请求方向。
- **cue 时间服从全局时间轴**：短 cue 可以短于建议最短时长；结束时间不能越过下一条 cue 的真实开始时间，并受媒体时长上限约束。排序、有限值、`startMs < endMs` 和全局不重叠都在导出前校验。
- **Karaoke 优先使用真实时间**：渲染消费与原文字符索引对应的 TTS 字级时间戳；只有时间戳缺失或不可信时才用整句均匀进度回退。
- **排版完整性优先于偏好行数**：`maxLines` 是排版偏好，不得导致无提示截字。安全缩放耗尽后要么继续增加行数保文，要么返回带明确状态且 UI 可见的溢出/截断结果。

## P1：保护句子数据与翻译可信度

### 1. 翻译完成后合并到最新文档，不回写旧句子快照

涉及：`components/subtitle-panel.tsx`、`lib/core/subtitle/secondary.ts`。

当前翻译基于请求开始时的 `doc.lines` 生成整份 `result.lines`，请求完成后覆盖 `current.lines`。这会回滚请求期间的文案、锁定、语气、段落录制和其他句子字段。

执行要求：

- 让翻译结果按 `lineId` 返回译文及其请求源文哈希，不把旧 `Line` 对象作为最终写回数据。
- 在 `setDoc` 的最新 `current` 上按 ID 合并，只更新 `secondaryText`、`secondaryHash` 这两个翻译字段。
- 写回前比较当前 `line.text` 的哈希与请求时源文哈希。源文已变化时跳过旧译文，保留该句待更新状态。
- 请求期间被删除的句子跳过；请求期间新增的句子保留且不被旧结果移除。
- 组件切换面板或卸载时，仍不得让过期结果覆盖新文档；取消请求时清理 loading 状态。

验收测试：

- 翻译 promise 未完成时改句子文本，resolve 后文本保持新值，旧译文不写入，新句保持待翻译。
- 翻译 promise 未完成时修改 `locked`、`voiceTag`、`pauseAfterMs` 或隔离字段，resolve 后这些字段保持新值。
- 翻译期间新增或删除句子，完成后新增句保留、删除句不复活。
- 未变化句子可以正常写入新译文和匹配的 `secondaryHash`。

### 2. 翻译方向按句确定，并支持语言方向覆盖

涉及：`components/subtitle-panel.tsx`、`lib/core/subtitle/secondary.ts`、`app/api/subtitle/translate/route.ts`。

当前面板仅检测第一条非空句子，并把方向应用于所有句子。混合语言稿、外语开场或中文稿以英文句开头时，后续翻译方向可能错误。

执行要求：

- 默认逐句识别语言，不以第一句的结果覆盖全篇。
- 翻译 API 按源语言分组请求，或在每个 unit 中传递 `from`；服务端质量检查使用该 unit 自己的方向。
- 面板提供清楚的语言模式：自动按句识别、统一中文源文、统一英文源文。自动模式为默认值。
- 源文方向不确定或只有数字/符号时，不生成猜测方向的译文；将该句显示为待处理，并说明原因。
- 重新补译时，保留仍有效的译文；只提交缺失、语言错误或源文哈希过期的句子。

验收测试：

- 中文、英文交错的两句分别请求英文和中文译文。
- 统一语言模式对所有句子使用明确选择的方向。
- 一句源文改变后只更新该句，不覆盖其他有效翻译。
- 翻译方向与目标文字系统不符的响应被拒绝。

### 3. 统一客户端和服务端译文质量判断，重试耗尽后拒绝坏结果

涉及：`app/api/subtitle/translate/route.ts`、`lib/core/subtitle/secondary.ts`。

当前服务端最终写入前只检查目标文字系统。超过全局 16 次额外调用上限后，仍可能保存过长或长度比例异常的译文。

执行要求：

- 将“目标语言正确、源文与译文长度比例合理、字幕长度上限”收敛为一套共享规则，避免客户端/服务端阈值分叉。
- 重试预算按条目管理，或保留全局调用上限但把未通过质量检查的条目标记失败；不能因预算耗尽而放宽验收。
- 每次响应写入前必须重新执行完整质量校验。校验失败的条目不返回为成功，不计算为已覆盖。
- 错误结果不得覆盖现有有效翻译；响应提供成功数、失败数及可供 UI 展示的简短失败原因。
- 增加 API 路由测试，通过 mock `generateJson` 覆盖缺 ID、错语言、超长、比例异常、重试耗尽及部分成功。

验收测试：

- 重试预算耗尽后，超长或比例异常译文仍被拒绝。
- 部分成功只写入通过完整校验的行，失败行保持待更新。
- 服务端与客户端对同一组中英文样本得出相同的质量判断。

### 4. 缺少 `secondaryHash` 的旧译文应显示为待更新

涉及：`lib/core/subtitle/secondary.ts`、`components/subtitle-panel.tsx`。

当前无哈希译文可通过 `isSecondaryUsable`，但又会进入待翻译队列；覆盖率因而显示全新鲜，UI 同时隐藏补译按钮。

执行要求：

- 明确“可显示”与“确认新鲜”是否为不同状态。缺少源文哈希时不得统计为已验证的新鲜译文。
- 让覆盖率、待翻译队列和渲染规则共享相同状态判定，避免一个函数判新鲜、另一个判待翻译。
- 对无哈希的兼容数据提供可见的待验证/待更新状态和可执行的补译入口。

验收测试：

- 有译文、无哈希的行不会导致“覆盖率全满但没有补译入口”。
- 哈希匹配、哈希不匹配、缺失哈希三种状态在覆盖率和队列结果中一致。

## P2：字幕完整性、时间与渲染

### 5. 排版永不静默截掉原文

涉及：`lib/core/subtitle/formatter.ts`。

`wrapText` 超过 `maxLines` 时直接切片丢弃余下文本，双语行也受影响。排版器需要明确处理“最大行数”和“原文必须完整”之间的冲突。

执行要求：

- 让排版结果携带完整性状态或保留全部文字；不得把裁切后的结果伪装成成功排版。
- 先在安全宽度内换行，再按明确的最小字号策略缩小。达到最小字号仍无法满足用户行数偏好时，使用产品约定的安全降级：增加行数以保全文本，或返回明确的截断状态供界面提示。不得无提示丢字。
- 中英文、手动换行和双语副行使用同样的完整性规则。
- 使用 Unicode grapheme 边界处理字符，避免 emoji 或组合字符被从代理项中间拆开。
- 加入测试断言：去掉布局分隔符后，排版文本与输入文本一致；若选择显式截断，则必须断言状态及可见省略提示。

验收测试：

- `maxLines=2/3/4` 下的超长中文句子完整可见。
- 中英文混排、显式换行和双语长副行不丢字。
- 超长文本不会超出画布安全宽度；无法容纳时走已定义的显式降级状态。
- Emoji、旗帜和组合音标不会出现半个字符或错误分割。

### 6. 连续西文 token 需要二次断词

涉及：`lib/core/subtitle/formatter.ts`。

当前西文只按空格拆分。单个 token 比安全宽度更长时不会拆开，字号只尝试有限次数后仍可能溢出。

执行要求：

- 普通英文优先按单词换行；单词本身过宽时按 grapheme 安全边界拆分。
- URL/邮箱等可识别 token 可在合适标点处优先断开；不允许为避免溢出直接切掉尾部。
- 排版完成后显式验证每一行测量宽度不超过安全宽度；失败时进入第 5 项的明确降级逻辑。

验收测试：

- 120 个连续 ASCII 字符、超长网址和长数字串不会越过安全宽度或被截断。
- 普通英文单词不会为了均分而被不必要地拆开。

### 7. SRT cue 的时间必须按全局时间轴约束

涉及：`lib/core/subtitles.ts`、`lib/core/timeline.ts`。

当前 800ms 最短显示时长只在单行内部修正，没有限制在下一句开始前。短句可把后一句字幕挤进同一时间段。

执行要求：

- 将最短时长视为建议值而非硬约束；cue 结束时间不得超过下一条 cue 的开始时间或产品明确允许的边界。
- 在整条时间轴上做最终排序和边界校验，不只在 `cuesForLine` 的局部范围内处理。
- 若时长不足以容纳最短时长，优先保证不重叠；必要时允许短 cue，或调整字幕分组，不得把结束时间推到下一句之后。
- 校验时间为有限值且 `startMs < endMs`；输出 SRT 前再次断言 cue 顺序和非重叠条件。

验收测试：

- 200ms 的“好。”后接 250ms 默认停顿，第一条字幕结束不晚于下一句开始（450ms）。
- 多条短句、同句多 cue、段落自然停顿和缺少字级时间戳的估算场景均不产生重叠。
- `toSrt` 输出 cue 顺序稳定，所有时间戳有效。

### 8. Karaoke 高亮使用真实 TTS 字符时间

涉及：`lib/core/timeline.ts`、`remotion/layers/subtitles.tsx`。

当前高亮按整句总进度均匀推进，无法反映字与字之间的实际语速和停顿。

执行要求：

- 给字幕块传递与原文字符索引一致的逐字时间，渲染时根据当前帧选出已读字符范围。
- 校验 TTS 时间戳与原文索引映射；缺失或估算配音使用均匀进度回退，不得生成 NaN 或越界高亮。
- 排版折行后仍按原文偏移映射颜色，标点、emoji 和中英文混排不改变后续字符的时间对应。

验收测试：

- 构造前半句慢、后半句快及中间长停顿的字符时间，断言高亮边界随时间戳走，而不是随字符总数线性走。
- 预览与 Remotion 最终渲染同帧显示相同的高亮范围。

## P2：翻译与界面体验

### 9. 长翻译任务显示真实进度并可停止

涉及：`lib/core/subtitle/secondary.ts`、`components/subtitle-panel.tsx`。

当前多批翻译串行等待，只显示一个 spinner，没有当前批次、完成数量或停止入口；已有 `signal` 参数但面板没有使用。

执行要求：

- 为批次翻译增加进度回调，UI 显示已完成/待处理句数；不要只显示一个不定时 spinner。
- 使用 `AbortController` 提供停止入口，停止后不再提交后续批次，并在 UI 显示已完成数量。
- 明确取消语义：建议已返回且通过校验的批次保留，未完成批次不写入；取消按钮进入“正在停止”状态，直到请求收尾。
- 组件卸载时清理 controller；旧请求的 finally 不得关闭新请求的 loading 状态。

验收测试：

- 多批请求时进度单调增加，结束后清理状态。
- 用户停止后没有新批次发出，已完成且有效的译文保留，未完成句仍可再次补齐。

### 10. 字体选择器按需加载并区分加载失败

涉及：`components/subtitle-panel.tsx`、`lib/core/subtitle/fonts.ts`。

展开中文选择器会并行加载四个内置字体文件，合计约 13.2 MiB。字体样例在失败时也会一直显示“正在载入字体…”。

执行要求：

- 只在字体卡片需要展示或被选择时加载对应字体，可用可见性触发懒加载；不要在展开时无条件加载整个字体集合。
- 字体状态至少区分未加载、加载中、已就绪、加载失败；失败状态说明当前预览将使用系统回退，并提供重试入口。
- 已选择字体加载失败时，预览和成片都回退到同一字体，UI 明确显示实际回退状态。

验收测试：

- 展开选择器不会请求所有字体文件；滚动到某卡片或选择它时才加载对应文件。
- 模拟 404/FontFace 拒绝时，卡片不无限显示加载中，用户能辨认回退字体。
- 加载成功后样例、预览与最终渲染使用同一字体。

### 11. 预设效果和文案一致

涉及：`lib/core/subtitle/presets.ts`、字幕渲染器、字幕面板。

至少核对“赛博霓虹发光”的外发光和“复古打字机”的等宽字体描述。当前对应预设没有完整实现这些效果。

执行要求：

- 逐项对照六个预设的名称、说明、卡片示例和真实输出。
- 选择之一：补齐承诺的视觉效果；或把无法由现有字体/渲染支持的文案改为准确描述。
- 若用户手动修改预设中的组成设置，UI 应区分“仍匹配预设”和“自定义组合”，不能继续让卡片状态造成误解。
- 检查预览和最终渲染在背景、描边、阴影、颜色和字体上的一致性。

验收测试：

- 六个预设各有配置断言和至少一个渲染级视觉核对。
- 预设卡片描述的效果在预览与导出中都能观察到；手动改动后自定义状态准确。

### 12. 字号控件说明基准尺寸

涉及：`components/subtitle-panel.tsx`、`lib/core/subtitle/types.ts`。

控件直接显示 `px`，但字号以 950px 画面为基准，渲染按视频宽度缩放。

执行要求：

- 将控件命名为“基准字号”或明确显示“px（按 950px 画面基准）”。
- 保持实际导出像素大小可解释；预览可继续作为结果反馈，不要暗示 24 就一定是成片 24px。
- 检查滑块范围和配置 schema 范围是否一致，并决定是否同步。

验收：

- 横屏和竖屏下，面板提示都能解释缩放关系；范围与配置约束一致，或有明确产品理由。

## P3：无障碍与键盘操作

### 13. 修复字体选择器和行数按钮的语义

涉及：`components/subtitle-panel.tsx`。

- 让字体卡触发器的 `aria-controls` 指向真实存在且稳定的选项容器 ID。
- 为最大行数选项提供单选语义，例如 `radiogroup` / `radio`，或为普通按钮添加 `aria-pressed`。
- 让辅助技术可读取当前字体、当前行数、展开状态和字体加载/失败状态。
- 验收键盘 Tab、方向键（若用 radio）、Enter/Space、Escape；焦点不能落入折叠且不可见的选项。
