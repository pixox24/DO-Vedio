# 第四批体验优化实施计划

> 基于 `docs/ux-review.md` 第 4、7 节，以及当前 P0/P1/P2 已有实现整理。
> 本批目标：提高分镜编辑效率、降低读音修改成本、让生成操作可恢复，并让占位画面在正式接入素材前也具备可观看性。

## 1. 批次目标

第四批完成后，用户应能完成以下闭环：

1. 在分镜板直接看到每个镜头的缩略图、覆盖句子和时长，点击镜头即可跳到预览对应位置。
2. 在句子中选中文字设置读法，试听新的整句读音，并明确知道该词典规则会作用于哪些位置。
3. 在全文重写、重新生成大纲、段落 AI 改写前自动留下版本，之后能浏览、恢复，并且恢复操作本身也可回退。
4. 在制作页使用空格、J/K、`Cmd/Ctrl+S` 等快捷操作，不干扰输入框原生编辑。
5. 没有真实图片时，Remotion 占位画面仍有明确版式变化、亮度层次和入场动画，不再连续显示同一种深色渐变。

本批不接入新的图片或视频供应商，不做完整时间轴拖拽编辑，不做团队权限和云端协作。

## 2. 当前基础和主要缺口

### 已有基础

- `buildTimeline()` 同时供预览、渲染、SRT 使用，镜头已经有 `startMs`、`endMs`、`caption`、`keywords` 和 `seed`。
- `VideoPreview` 使用 `@remotion/player`，目前已经支持按毫秒跳转。
- `Shot` 已有候选素材、锁定、首尾帧、控制图、角色卡和场景卡字段。
- 词典已经支持项目级作用域，`applyLexicon()` 能按最长匹配生成 `spans`。
- `useProject()` 已有 revision、三方合并和冲突处理，但还没有文档撤销栈和服务端版本快照。
- SQLite 迁移按递增编号执行，已有 `generation_runs` 可供操作记录参考。

### 主要缺口

- 分镜卡片只有表单和候选小图，默认镜头没有统一缩略图，也没有显示覆盖范围。
- 词典入口依赖手填词语和读法，选中文字不能直接进入设置读法流程。
- 当前 revision 不是可供用户浏览的版本历史；每次自动保存也不适合直接当历史版本。
- 预览播放器只暴露 `seekToMs()`，没有统一的播放切换和当前句子状态接口。
- 占位画面只有一种渐变、网格、关键词布局；`TimelineShot` 没有稳定的占位版式字段。

## 3. 实施顺序和依赖

### 阶段 A：公共数据和接口约定

先完成版本快照迁移、时间轴镜头展示数据和预览控制接口，避免后续页面各自实现一套状态。

- 新增 `project_versions` 迁移，保存完整 `ProjectDoc` 快照，不修改现有 `projects.revision` 语义。
- 为版本快照增加服务端读写函数和路由：列表、创建、恢复。
- 扩展 `VideoPreviewHandle`：`togglePlayPause()`、`isPlaying()` 或等价的受控回调。
- 给镜头面板增加时间轴数据加载和 `onSeek(ms)` 回调。
- 新增共享的 `isEditableTarget()` 和快捷键处理 hook，统一处理输入框、选择框、文本域和 `contenteditable` 的排除规则。

验收：旧数据库自动完成迁移；项目保存、冲突合并、预览和渲染现有行为不改变。

### 阶段 B：分镜缩略图和镜头工作流

#### 页面改造

- 抽出 `ShotCard`，负责缩略图、状态、时长、覆盖句子和编辑区。
- 卡片顶部显示：镜头序号、`00:08–00:12`、覆盖第几句；缩略图固定比例，避免内容加载导致布局跳动。
- 有 `assetId` 时优先显示图片或视频首帧；无素材时使用与 Remotion 相同的占位版式预览。
- 对 `title`、`quote`、`placeholder` 使用轻量 `@remotion/player` 单镜头预览，设置 `preload`/懒加载，避免一次渲染所有镜头拖慢制作页。
- 点击缩略图或卡片标题调用 `onSeek(startMs)`；当前选中的镜头使用白色边框并自动滚动到可见区域。
- 卡片底部保留上传、生成、候选选择、拆分、合并；技术参数放入“高级”折叠区域。
- 候选数量移到分镜板顶部作为全局设置，每张卡片只显示候选结果。
- 生成中、没有素材、上传失败、候选切换失败都显示在卡片内部，不依赖页面顶部的单一错误文本。

#### 数据和性能

- `/api/projects/[id]/timeline` 返回的 `shots` 作为卡片时长和覆盖句子的唯一来源。
- 时间轴尚未有真实配音时，显示“估算”，并保留现有问题提示。
- 首屏只渲染可见缩略图；移动端单列，桌面端 2/3 列，缩略图尺寸固定。

验收：用户点击镜头后，预览跳到该镜头起点；卡片展示与渲染时间轴一致；横屏和竖屏只改变预览比例，不改变镜头顺序。

### 阶段 C：选中文字设置读音

#### 交互

- 句子正文改为可选择文本的容器，不再用整块按钮包住正文。
- `mouseup`/键盘选择结束后，验证选区属于当前句子且长度大于 0，显示浮动操作条“设置读法”。
- 点击后打开小弹层：原文只读、读法输入框、试听、保存、取消。
- 默认读法填充为选中文字，用户只需改成实际读法；保存后写入项目词典并重新排队当前句配音。
- 提示“该规则会作用于本项目中出现的同名词语”，避免用户误以为只替换一次。
- 试听调用现有 `/api/voices/preview`，传入当前句的完整朗读文本；保存后保留原文字幕不变。
- 保留键盘可达的“添加词典规则”入口，作为触屏和无法产生选区时的兜底。

#### 数据规则

- 仍使用 `POST /api/lexicon`，scope 为项目 ID；同一项目同一词语更新已有规则。
- 保存前校验原文和读法非空，禁止 HTML/控制字符；成功后刷新句子派生数据。
- 词典写入和重新配音分成两个可观察步骤：词典保存成功但排队失败时，明确提示用户可重试。

验收：桌面鼠标、触屏长按和键盘选区都能打开入口；保存后下一次朗读使用新读法；取消不会修改文档；重复添加同词语会更新而不是生成重复记录。

### 阶段 D：版本历史和恢复

#### 存储设计

新增迁移 `project_versions`：

| 字段 | 用途 |
|---|---|
| `id` | 快照 ID |
| `project_id` | 所属项目 |
| `revision` | 创建快照时的项目 revision |
| `label` | 用户可读原因，如“全文重写前” |
| `doc` | 完整 `ProjectDoc` JSON |
| `created_at` | 创建时间 |

增加 `(project_id, created_at DESC)` 索引。每个项目默认保留最近 50 个快照，清理也在同一事务中执行。

#### API

- `GET /api/projects/[id]/versions`：返回快照摘要，不直接返回完整文档列表，避免页面初始载荷过大。
- `POST /api/projects/[id]/versions`：在确认当前 revision 后保存快照，支持 `label`。
- `POST /api/projects/[id]/versions/[versionId]/restore`：在恢复前先保存当前文档为“恢复前版本”，再原子写入历史文档并递增 revision。
- 所有写操作检查项目存在和 revision；冲突时返回现有项目，沿用现有冲突处理方式。

#### 自动创建时机

只在高风险操作前创建，不把每次输入或 800ms 自动保存都记为版本：

- 全文重新生成前：`全文重写前`
- 重新生成大纲前：`重新生成大纲前`
- 单段 AI 改写前：`改写第 N 段前`
- 批量时长校准前：`时长校准前`
- 恢复历史版本前：`恢复版本前`

执行顺序固定为：先 `store.flush()`，再创建快照，再发起生成请求。生成取消或失败时快照仍保留，方便用户恢复。

#### 页面

- 在文案页项目栏加入“版本历史”文字按钮，打开右侧抽屉或移动端底部面板。
- 列表显示标题、时间、revision 和段落数量；打开详情时显示文案摘要，不自动覆盖当前内容。
- 恢复必须使用站内确认弹窗，说明当前未保存修改会先保存为一个新版本。
- 恢复成功后刷新 `useProject()` 状态、清空本地冲突状态和旧撤销栈。

验收：全文重写前能看到快照；恢复后文案、概要、大纲、标注、镜头和设置一起恢复；连续恢复不会丢失当前版本；刷新页面后历史仍存在。

### 阶段 E：快捷键和文档撤销

#### 快捷键

- 空格：制作页切换预览播放/暂停；焦点位于输入控件时不拦截。
- `J`：跳到上一句并将播放器定位到句首。
- `K`：跳到下一句并将播放器定位到句首。
- `Cmd/Ctrl+S`：取消默认保存行为，立即执行 `store.flush()`。
- `Cmd/Ctrl+Z`：页面级文档撤销；输入框、文本域和 `contenteditable` 中交给浏览器原生撤销。

#### 撤销实现

- 在 `useProject()` 中维护本地 `past` 栈，按 600–800ms 合并连续输入，避免流式生成每个字符占一个历史项。
- `setDoc`、恢复版本和冲突解决都要更新栈边界；服务端主动刷新文档时清空与旧 revision 相关的撤销项。
- 撤销后仍走现有自动保存和 revision 冲突流程，不绕过服务端校验。
- 在项目栏提供有无可撤销状态的无障碍标签；不新增常驻快捷键说明文字，避免增加视觉噪音。

验收：输入框内 `Cmd/Ctrl+Z` 仍能撤销正在输入的字符；页面空白处可撤销最近一次文档修改；保存和冲突处理不产生死循环。

### 阶段 F：Remotion 占位画面版式

#### 版式模型

在 `buildTimeline()` 中根据镜头 `caption`、`keywords`、数字和 `seed` 得到稳定的 `placeholderVariant`，不写回用户文档，保证预览和最终渲染始终一致。首批提供：

- `headline`：关键词大字、短副标题和入场下划线。
- `stat`：从句子提取数字或百分比，数字占主视觉。
- `list`：从关键词或短句生成两到三条要点。
- `split`：适合“前后、对比、与、但是”等句式的双色分屏。
- `quote`：短句居中排版，保留轻量引号和关键词高亮。

分类必须是纯函数、可测试、同一 `shotId/seed` 始终得到相同结果。

#### 视觉和动画

- 扩充 `theme.palettes` 的中间调和亮色，加入蓝、青、琥珀、红紫等有限组合，避免所有镜头接近黑色。
- 亮色只用于版式层级和关键词，保留品牌荧光绿的稀缺性。
- 统一加入 12–24 帧入场：大字上移、数字缩放、列表逐条出现、分屏擦入、下划线扫过。
- 文字根据长度和画幅使用稳定的最大宽度、字号和换行规则，避免中文溢出。
- 预览加载时显示首帧或明确的“正在加载预览”，避免纯黑空白。

验收：同一项目的预览和导出画面一致；连续 10 个占位镜头至少出现三种版式；390px/竖屏下文字不越界；无素材时仍能完成完整渲染。

## 4. 测试计划

### 单元测试

- `project_versions`：创建、按项目列表、50 条清理、恢复前自动留档、revision 冲突。
- 快照触发器：全文重写、段落改写、大纲生成和时长校准各只创建一次。
- `placeholderVariant`：数字、长句、对比句、关键词和 seed 的分类及确定性。
- 选区文本清洗：空选区、跨句选区、首尾空白、重复词语。
- 文档撤销栈：连续输入合并、流式更新合并、输入控件不被全局快捷键拦截。

### 集成和手工验证

- `npm test`
- `npm run typecheck`
- `npm run lint`
- `npm run build`
- `npm run smoke` 验证无素材占位画面能够渲染。
- 使用 1440px 和 390px 检查项目页、文案页、制作页；重点查看缩略图布局、浮动读音弹层、版本抽屉和竖屏版式。
- 从新建项目开始走一遍：生成大纲 → 全文生成 → 改写一段 → 恢复版本 → 设置读音 → 生成样片。

## 5. 风险和控制

| 风险 | 控制措施 |
|---|---|
| 每个缩略图都挂一个 Player 导致页面卡顿 | 懒加载、固定尺寸、只渲染可见卡片，真实素材优先使用图片/视频首帧 |
| 版本快照过多占用 SQLite | 只在高风险操作前创建，单项目保留 50 条，快照正文压缩前先保持可读 JSON |
| 选区浮层在触屏上位置错误 | 以 `Range.getBoundingClientRect()` 定位，超出视口时改为底部弹层 |
| 全局快捷键破坏输入 | 统一 `isEditableTarget()`，并为播放器和项目页分别注册作用域 |
| 占位版式与最终渲染不一致 | 所有版式由 `TimelineShot.placeholderVariant` 派生，预览与渲染共用 Remotion 组件 |
| 恢复历史时覆盖新修改 | 恢复前强制保存当前快照，并要求 revision 匹配；失败返回冲突而不是覆盖 |

## 6. 完成定义

第四批只有在以下条件全部满足时才算完成：

- 分镜缩略图、时长、覆盖句子和点击跳转在横竖屏下可用。
- 选中文字可设置读法、试听并触发当前句重新配音。
- 高风险 AI 操作前自动留档，版本可浏览、恢复、再次恢复。
- 快捷键在制作页和文案页生效，输入框原生操作不受影响。
- 占位画面具备至少三种稳定版式和入场动画，预览与导出一致。
- 单元测试、构建检查、渲染冒烟和 1440/390 两种视口验收全部通过。
