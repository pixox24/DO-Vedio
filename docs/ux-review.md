# 体验评审：交互、布局与视觉

> 评审日期：2026-09-25 ｜ 范围：项目列表、文案页（`/projects/[id]`）、制作页（`/projects/[id]/video`）、风格模板、模型中心，以及成片画面
> 方法：通读页面组件代码，并用无头 Chrome 分别在 1440px 和 420px 宽度截图。没有做真人点击测试，结论需要在真实使用中复核。

---

## 0. 结论

整体视觉语言（深色底、荧光绿强调色、细边框面板）已经统一，文案页的完成度最高。主要问题不在"好不好看"，而在三件事：

1. **有两个按钮会不加确认地清空文案**，属于数据丢失级问题，必须先修。
2. **制作页是"一堆表单从上往下排"，不是一个剪辑工作台**。预览不是中心，句子、镜头、时间三者之间没有联动，最重要的决定（音色）排在最后面。
3. **状态信息不可信**：进度数字把历史任务也算进去（8 句话显示"配音 25/25"），成片列表不告诉你哪一条是最新的、是否已经过期。

优化目标可以概括成一句话：**用户始终清楚"现在在哪一步、下一步点哪里、这一下要花多少钱、做错了能不能退回去"**。

## 2. 信息架构和导航

**2.1 步骤编号有三套，彼此矛盾。** 顶部是「项目 / 风格模板 / 模型中心」，项目内是「01 文案 / 02 制作」，文案页里又有「Step 00 选题 / Step 01 大纲 / Step 02 文案」。结果是在「01 文案」标签下看到大标题「STEP 02 · 文案」。
→ 建议统一成一条贯穿全流程的步骤条：**选题 → 大纲 → 文案 → 配音 → 分镜 → 成片**。每一步显示完成状态，可以点击跳转；页面内不再另起一套编号。

**2.2 标题重复出现三次。** 文案页里，项目名同时出现在面包屑、页面大标题和左侧「视频标题」输入框中。
→ 保留面包屑和输入框即可。大标题的位置留给当前步骤要做的事，比如「文案 · 3 段 · 预计 00:29」。

**2.3 每一步结束时没有指向下一步的按钮。** 文案写完以后，页面上看不到「去制作视频」；成片做完以后，也没有「去填发布信息」。
→ 每个阶段结束时，给出唯一一个明确的「下一步」主按钮。

**2.4 「发布素材」放在文案页底部**，但它依赖的是最终成片（时长、章节时间戳要以真实配音为准）。
→ 挪到成片之后，章节时间戳改用真实的时间轴计算，而不是按字数估算。

**2.5 顶部「模型中心」和风格模板属于管理功能**，与日常创作放在同一层级。单人使用可以接受；如果团队使用，建议收进右上角的「设置」。

## 4. 制作页（改动最大的部分）

### 4.1 布局：从"表单堆叠"改成"剪辑工作台"

现在从上到下依次是：按钮行 → 步骤条 → 预览和成片列表 → 句子和设置 → 分镜板 → 配乐。页面很长，而最直观的分镜板被压在最底部。

建议的布局（桌面端）：

```
┌ 顶栏：步骤条（配音 ▸ 分镜 ▸ 配乐 ▸ 成片） · 费用 · 主按钮「生成成片 ¥0.12」 ───────┐
├──────────────────────────────┬──────────────────────────────────────┤
│ 预览播放器（sticky）          │ 右侧标签页：句子 │ 镜头 │ 配乐 │ 设置 │
│ 16:9 / 9:16 切换             │  · 当前播放到的句子或镜头自动高亮、滚动到可见 │
├──────────────────────────────┤  · 点击任意一项，播放器跳到对应时间     │
│ 横向时间轴条：句子 / 镜头 / 配乐三条轨 │                                      │
└──────────────────────────────┴──────────────────────────────────────┘
成片：最新版本（横 + 竖）置顶显示，历史版本折叠
```

要点：
- **预览是中心**。点句子、点镜头、点配乐片段都能跳到对应时间；播放时右侧列表跟着走。原方案里写过「点击句子 → 播放器跳转」，目前还没有实现。
- **时间轴条**不需要支持拖拽编辑，只要能把句子、镜头、配乐三者在时间上的对应关系画出来，用户就能理解"这个镜头覆盖了哪几句话"。
- 手机端：预览放在顶部，下方是标签页，不再并排。

### 4.2 流程顺序：先定音色，再花钱

音色、语速、画幅放在页面最底部的「制作设置」里。但一键成片之后再换音色，所有句子都要重新配音、重新花钱。

→ 第一次进入制作页时，先给出一个简短的开工确认：**音色（可试听）、画幅、预算**，确认后再显示「生成成片」。之后如果修改音色，提示「将重新配音全部 8 句，约 ¥0.05」。

### 4.3 主操作

| 问题 | 建议 |
|---|---|
| 「一键成片」和「快速样片」的区别只能靠猜 | 按钮下方加一句说明：「样片：低清，约 30 秒，用来确认节奏」「成片：1080p，横竖两版」 |
| 点快速样片时，转圈的却是「一键成片」按钮 | 转圈状态跟随实际点击的按钮 |
| 预估费用只是角落里的一行小字，点击前看不到这一步要花多少 | 把费用写进按钮本身，例如「生成成片 · 约 ¥0.12」；超出预算时用站内弹窗说明 |
| 「停止」会取消全部任务，没有确认 | 加确认，并说明已完成的部分会保留、下次会接着做 |
| 16:9 / 9:16 切换只影响预览，不影响渲染哪几种画幅，容易误解 | 预览切换和「输出画幅」分开；输出画幅放进开工确认和设置里 |
| 「已暂停：……」和等待原因是灰色小字 | 做成带操作按钮的状态条，例如「第 3 句配音失败：音色不支持 · [换音色] [重试]」 |

### 4.4 句子面板

- 每句一个浏览器原生 `<audio>` 控件，8 句就是 8 条系统播放条，视觉很重，而且每个平台长得都不一样。→ 换成统一的小播放按钮加波形或进度；更好的做法是直接让主播放器跳过去播放。
- 「重录」一直显示，点击就花钱，却没有任何提示。→ 放进「更多」菜单，旁边标出预计费用。
- 加读音词典要手动输入词语。→ 改成在句子里**选中文字**，直接弹出「设置读法」，并当场试听。
- 「锁定」具体锁定了什么（标注？配音？），界面上没有说明。→ 悬停时说明「锁定后不会被自动重新标注或重录」。
- 「朗读：…」一行和原文几乎一样，信息量低。→ 只在朗读文本与原文不同时显示，并高亮不同之处。

### 4.5 分镜板

- 现在是一格一格的表单（两个下拉框、多个输入框、seed 数字框），看不到画面。→ 每个镜头卡片以**缩略图**为主（可以用 `@remotion/player` 的 `Thumbnail` 渲染该镜头的中间帧），显示时长和覆盖的句子；编辑项收进侧边抽屉。
- 下列技术参数不应该出现在默认视图里：`seed`、候选数量、生成提示词。→ 放进「高级」区域。
- 「拆分」只能在下一句的开头切开，用户无法选择切点。→ 在句子里选择切分位置，或者在时间轴条上点选。
- 候选数量是全局状态，却放在每张卡片里，改一张等于改所有张。→ 移到分镜板顶部统一设置。

### 4.6 配乐和设置

- 原生复选框、原生滑块，和其他页面的视觉不统一。→ 统一用开关组件和带数值的滑块。
- 曲库为空时提示「运行 `npm run library:ingest`」，Worker 离线时提示命令行命令。内部工具可以保留，但应该加上面向普通用户的说明，例如「请联系管理员导入曲库」，命令放在折叠的详情里。
- 看不到配乐片段覆盖了时间轴上的哪一段。→ 在时间轴条上画出配乐轨。
- 语速范围 0.5–2 倍太宽，常用区间是 0.85–1.25 倍。→ 收窄范围，或者改用「慢 / 标准 / 快」加微调。
- 响度数值（LUFS）直接展示给用户，属于专业术语。→ 默认显示「响度正常」，把具体数值放进详情。

## 5. 项目列表

- 卡片下半部分是空的，只有两行小字；操作按钮只在悬停时出现，触屏上完全点不到。→ 加封面（最新成片的一帧或占位图）、状态标签（文案中 / 配音中 / 已出片 / 渲染失败）、最后一次成片的时长；操作收进「⋯」菜单，始终可见。
- 「新建项目」会立刻创建一个空项目，不填内容退出后就留下一个「未命名项目」。→ 先弹出一个只填标题的小窗，或者在第一次保存有内容时才真正创建。
- 项目多了以后没有搜索和排序。→ 超过 12 个项目时显示搜索框。

## 6. 视觉和审美

**6.1 强调色用得太满。** 荧光绿同时被用在主按钮、选中态、完成勾、关键词高亮、项目标签激活态、进度条上，每一处都在抢注意力，反而没有一处真正突出。
→ 荧光绿只留给两件事：**唯一的主操作**和**关键词高亮**。完成状态改用中性的白色勾，选中态用白色描边。

**6.2 激活态样式不统一。** 顶部导航激活是白底黑字，项目标签激活是绿底黑字，画幅切换是白底黑字。→ 同一类控件用同一种激活样式。

**6.3 文字对比度不够。** 大量次要文字使用 `text-white/25`～`/40`，字号 11–12px。在 #050505 背景上，`white/35` 的对比度约为 3:1，低于 WCAG 对小字要求的 4.5:1。项目卡片上的「1 分钟 · 4 段文案」、各种提示文字都读起来吃力。
→ 次要文字最低使用 `white/55`，辅助说明最低 `white/45` 并配合 13px 以上的字号；在设计令牌里把这几档固定下来，禁止随手写透明度。

**6.4 中文产品里混着英文大写小标题。** 「PROJECTS」「VOICE LINES」「STORYBOARD」「STYLE LIBRARY」加宽字距，属于装饰性噪音，对中文用户也没有信息量。→ 改成中文小标题，或者直接去掉。

**6.5 制作页和文案页像是两套产品。** 文案页的间距、圆角、层次比较讲究；制作页的面板内部挤满了 `chip` 和输入框，按钮、开关、标签全用同一种 chip 样式，没有层次。
→ 抽出一套基础组件：主按钮、次按钮、文字按钮、开关、分段控件、标签、带数值滑块、音频播放按钮、确认弹窗、轻提示。制作页全部改用这套组件。

**6.6 字号层级太碎。** 页面上同时出现 10、11、12、13、14、15px 等多种字号。→ 收敛成 4–5 档（例如 12 / 14 / 16 / 20 / 30），行高固定。

**6.7 成片画面（Remotion 占位镜头）。** 占位镜头都是深色渐变加一个半透明的关键词水印，连续看几十秒会显得单调，像没做完。在 P2 接入 AI 生图之前，建议：
- 占位画面增加版式变化：大字关键词排版、数字突出、要点列表、分屏对比，按句子内容选择版式。
- 调色盘增加亮色和中间调，不要全是接近黑色的底。
- 金句卡、章节卡加入入场动画（逐字出现、下划线扫过），弥补画面静止的问题。

**6.8 其他细节**
- 开发环境左下角的 Next.js「N」标识盖住了页面内容，生产环境不会出现，但截图和演示时要注意。
- 预览播放器加载时是一大块纯黑区域，没有任何提示。→ 显示首帧海报或「正在加载预览」。

## 7. 可访问性和操作效率

- 只在悬停时出现的操作（项目卡片、段落改写、删除章节），键盘和触屏用户都够不到。→ 获得焦点时显示；触屏上默认显示。
- 没有可见的焦点样式的自定义按钮（比如 `chip`）需要补上 `focus-visible` 描边。
- 图标按钮（撤销、删除）缺少 `aria-label`。
- 快捷键：空格播放或暂停预览；`J` / `K` 在句子之间跳转；`⌘S` 立即保存；`⌘Z` 撤销文档修改。
- 保存状态在项目栏和设置面板里各显示一次。→ 只在项目栏显示。

## 8. 建议的实施顺序

| 批次 | 内容 | 目的 |
|---|---|---|
| **第一批（1–2 天）** | 第 1 节全部：两个清空文案的按钮、手机端溢出、进度只统计当前计划、成片标出最新和过期、站内弹窗和轻提示 | 不丢数据，状态可信 |
| **第二批（3–5 天）** | 制作页改成工作台布局（4.1），加开工确认（4.2），完善主操作（4.3），实现点句子跳转预览 | 用户能看懂、能控制 |
| **第三批（3–4 天）** | 基础组件库和设计令牌（6.1–6.6），统一全站视觉；项目列表加封面和状态（第 5 节） | 整体质感 |
| **第四批（持续）** | 分镜缩略图（4.5）、选中文字设置读音（4.4）、版本历史（3.4）、快捷键（第 7 节）、占位画面版式（6.7） | 效率和成片观感 |

每批完成后，用同样的方法在 1440px 和 390px 下截图对比，并请一位没用过的人从零走完「新建项目 → 出片」，记录卡住的地方。
