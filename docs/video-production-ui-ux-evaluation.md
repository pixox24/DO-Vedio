# 视频制作模块 UI / 交互评估

> 日期：2026-10-02
>
> 范围：`/projects/[id]/video` 制作页，以及从文案进入制作、配音、生图、分镜、配乐、预览、渲染和下载的完整工作流。
>
> 目标：让用户随时知道“当前做到了哪一步、正在发生什么、还要等多久、失败后怎么继续、这次操作会影响什么”，并让预览和编辑保持稳定的视觉锚点。

## 结论

当前制作页已经有 SSE 任务状态、批次停止、成本提示、Worker 状态、过期成片标记和基础动效。主要问题已经从“没有反馈”转为四个更具体的体验风险：

1. **信任风险**：确认过的设置可能已经变化，仍被视为已确认；切换页面时 `flush()` 没有等待，最后一次编辑可能还没保存就卸载。
2. **状态风险**：取消、重试、网络断线和刷新失败缺少稳定的中间态；用户会看到旧进度，却不知道页面是否仍在工作。
3. **空间风险**：切换“句子 / 画面风格 / 角色 / 镜头”等面板会改变左右栏比例，预览和时间轴跳动；长面板又形成页面滚动与面板滚动的双重滚动。
4. **编辑效率风险**：时间轴只有 3px 色条，没有播放头、刻度、拖拽和内容提示；成片只有下载链接，没有直接预览、重新生成或按画幅查看的操作。

这次建议先修 P0 的数据与反馈可信度，再做 P1 的制作状态和时间轴，最后收敛桌面与移动端布局。动效应该服务于状态变化，不能用持续闪烁替代明确文案。

## 证据与优先级

### P0：先修信任和可恢复性

#### 1. 开工确认没有绑定设置快照

**证据**：`components/video-studio.tsx:77,180-183,274-300`。`setupConfirmed` 只写入 `sessionStorage`，键只包含项目 ID；确认后用户仍可在设置面板修改音色、预算、画幅和素材策略，页面不会重新要求确认。

**用户后果**：用户以为确认的是 A 设置，实际点击生成时已经使用 B 设置；尤其是预算和音色变化，会造成计费和成片规格预期不一致。

**修复**：计算一份只包含会影响付费或输出的 `setupHash`（音色、目标画幅、画质、素材策略、预算、模型）；持久化 `{ confirmed: true, setupHash }`。设置 hash 改变后立即显示“制作设置已变更，需要重新确认”，禁用生成按钮直到复核完成。弹窗中同时显示变化前后差异。

**验收**：确认后改音色、预算、画幅、素材策略分别会撤销确认；只改字幕颜色等不影响费用的设置不要求重新确认。

#### 2. 项目页切换没有等待保存

**证据**：`components/project-bar.tsx:36-40` 的链接 `onClick={() => store.flush()}` 没有 `await` 或阻止默认导航。

**用户后果**：用户刚编辑句子或镜头描述就切到另一个页面，路由可能先卸载组件，最后一笔修改没有落盘。

**修复**：使用 `router.push` 替代裸 `Link` 点击；点击后进入“正在保存…”，等待 `flush()` 成功再跳转。返回 `null`、冲突或网络错误时留在当前页，聚焦可操作的错误条，并提供“重试保存 / 放弃本次修改”。

**验收**：人为延迟 PUT 请求时切换页面，修改始终保留；保存失败时不会离开页面。

#### 3. JobStrip 的取消和重试没有可靠反馈

**证据**：`components/job-strip.tsx:33-57,90-96`。批量重试使用 `Promise.all`，失败没有内联错误；取消使用 `forEach(jobAction(...))`，不等待、不显示“正在取消”、不确认影响范围，也不处理部分成功。

**用户后果**：用户点击后看不到请求是否发出，可能重复点击；任务仍运行时，界面看起来像没有响应。

**修复**：为每个步骤维护 `canceling` / `retrying` 状态；取消前复用统一确认文案，提交后显示“正在停止…”，等待所有结果后显示 `已取消 n 个，m 个仍在执行`。重试使用 `Promise.allSettled`，成功和失败分别汇总，并提供再次重试。按钮在请求期间禁用。

**验收**：网络慢、部分接口失败、重复点击、Worker 延迟 10 秒生效时，状态都可解释；不会出现点击后静默失败。

#### 4. SSE 或刷新失败时页面会静默变旧

**证据**：`lib/client.ts:367-381` 只注册 `jobs/revision/worker/spend`，没有 `EventSource.onerror`、重连状态或最后更新时间。`components/video-studio.tsx:101-145` 的 `refresh()` 没有统一错误状态；刷新进行中再次触发时直接 `return`，没有 trailing refresh。

**用户后果**：连接断开后进度停在旧数字，用户无法区分“任务很慢”和“页面已经不再接收事件”。快速编辑和后台任务同时触发时，最后一次刷新可能被丢掉。

**修复**：

- 在事件订阅中加入 `connected / reconnecting / offline / lastEventAt` 状态和指数退避重连。
- 顶部状态条显示“实时连接正常 · 12 秒前更新”或“正在重新连接，页面可能不是最新”。
- `refresh()` 使用 request token，旧响应不能覆盖新 aspect；in-flight 结束后若有 pending refresh，再执行一次。
- 将请求错误分为“动作失败”和“数据同步失败”，同步失败提供“立即刷新”，不要只写一个普通红色 div。

**验收**：关闭 SSE、延迟 timeline 请求、快速切换横竖屏时，页面有明确状态且最终显示最新数据。

#### 5. 旧制作目标会从界面消失，停止范围也过大

**证据**：`components/video-studio.tsx:255-258` 只保留 `plan.plan.currentKeys` 对应的 jobs；用户在制作中修改文案、画幅或设置后，旧 key 的运行、排队和失败任务会被过滤掉。`components/video-studio.tsx:207-217` 调用项目级 stop，服务端 `app/api/projects/[id]/produce/route.ts:48-50` 使用 `cancelProjectJobs(id)`。

**用户后果**：进度会凭空归零，停止按钮消失，旧失败任务没有重试入口；更严重的是“停止制作”可能同时取消用户从句子或镜头面板单独发起的任务。旧目标仍可能产生费用，但用户看不到它。

**修复**：

- 为一键成片写入独立 `goalId/batchId`，停止只取消本目标提交的任务；独立重录和单镜生图保留。
- 活跃但不属于当前 key 的任务单列为“旧版本任务仍在运行”，保留取消、费用和失败重试入口。
- 新目标开始前若发现旧目标仍在执行，显示“继续等待 / 取消旧目标后开始”选择。
- 取消运行中任务使用“已请求停止，等待服务确认”状态，不把数据库状态瞬间伪装成供应商请求已经终止。

**验收**：编辑文案后旧任务仍可见；停止一键成片不会取消独立配音/生图；所有被取消任务都有最终确认事件或明确的服务商计费提示。

### P1：让制作过程可读、可控

#### 6. 步骤条只有汇总数字，没有全局进度叙事

**证据**：`components/job-strip.tsx:60-100` 每步只有 `done/total`、一行截断消息和 2px 进度线；`components/video-studio.tsx:329-337` 只额外显示 waiting 文案。

**问题**：用户不知道当前主阶段、前置依赖、剩余阶段、预计时间和阻塞原因；“等待分镜”与“分镜任务失败”在视觉上也没有统一的处理方式。

**修复**：增加一个“制作总览”状态带：`当前阶段 / 总体完成率 / 已完成任务 / 剩余阶段 / ETA`。步骤卡显示状态图标、阶段百分比、预计剩余时间和可展开任务列表。阶段依赖用细连接线表示，waiting 状态显示明确原因和跳转按钮。

**建议状态**：`未开始 → 排队中 → 执行中 → 部分完成 → 已完成`；失败和取消作为独立状态，不用颜色单独猜。

阶段汇总不能把所有任务简单等权平均：几十个配音任务加一个渲染任务时，平均百分比会严重误导。优先显示“当前阶段 x/y”；需要总进度时按阶段权重或预计耗时加权，无法估算的阶段显示不确定进度，并注明“仍有 n 个任务”。混合状态要显示“2 个失败，3 个仍在执行”，不能让任意一个失败覆盖整个阶段的活动状态；取消要有“已停止 n 个 · 继续”入口。

**动效**：进入执行中时只做一次 160ms 边框强调；进度条用 400ms ease-out 追随数值；完成时勾选图标 220ms 过渡后保持静态；不要让整个步骤卡无限呼吸。

#### 7. 生成批次在任务刚提交时可能没有任何可见进度

**证据**：`components/video-controls.tsx:511-523` 只有 `batchTotal > 0` 才渲染配音批次状态；`StoryboardPanel` 的批量生图也依赖事件流回填任务。

**问题**：提交成功到 SSE 首次到达之间，按钮恢复或状态条消失，用户会误以为任务没有提交。

**修复**：提交成功后立即显示“已提交，正在等待任务登记…”，使用 API 返回的 `count` 作为暂时分母；任务事件到达后替换为真实分母。状态对象要记录 `submittedAt`、`acceptedCount`、`done/failed`，不要用 0 个任务表示“没有任务”。

#### 8. 成片状态按画幅拆开，不能只显示一个全局“已过期”

**证据**：`components/video-studio.tsx:264,329-334` 的 `staleRender` 是一个布尔值；而 `RenderList` `:394-395` 实际按 `aspect` 判断新旧。

**问题**：16:9 已经是当前版本、9:16 已过期时，顶栏仍说“成片已过期”，用户不知道需要重做哪一个。

**修复**：顶栏显示 `16:9 最新 · 9:16 需重渲染`；主按钮根据选择的画幅显示“重新生成 9:16”。成片列表增加 `预览 / 下载 / 重新生成` 三个动作，并按画幅和质量分组。

生成按钮的目标也必须跟随计划状态：当设置 `pauseAfterPreview` 导致 `final` 请求实际只到样片阶段时，不能继续显示“生成成片”；应显示“生成样片并暂停”，并在按钮旁标出 `plan.generatedAt` / 对应文档 revision。计划仍在计算时不要显示“约 ¥0.00”，显示“正在计算费用”；计划 revision 过期时要求重新计算后才允许提交。

#### 9. 预览加载占位固定为横屏，会造成画幅跳动

**证据**：`components/video-studio.tsx:26,342` 动态组件 loading 和无 timeline 占位都使用 `aspect-video`，即使当前预览是 `9:16`。

**修复**：根据当前 aspect 使用 `aspect-[16/9]` 或 `aspect-[9/16]` skeleton，并保留 `timeline.width/height` 的稳定尺寸。时间轴更新时保留播放器当前帧，在预览上叠加轻量“预览已更新”提示，不整块闪烁。

#### 10. 预览没有与编辑状态形成即时联动

**证据**：`components/video-preview.tsx:20-30` 只启用 Remotion 默认 controls；`TimelineStrip` 没有读取当前播放帧。

**修复**：

- 播放时高亮当前句子、镜头和配乐 cue；编辑列表中对应卡片自动保持轻量高亮。
- 点击句子、镜头、配乐后 seek，并在播放器下方显示“当前：第 4 句 · 镜头 3”。
- 预览更新时显示 `保存中 / 时间轴重算中 / 使用旧时间轴` 的状态层。
- 给播放器补 `aria-label`、加载失败和渲染异常提示，避免黑屏只能猜原因。

渲染成功不能只静默刷新列表：应在当前页面短暂提示“16:9 成片已完成”，并提供“播放 / 下载”；停止后也要先展示“正在停止”，直到 SSE 或刷新确认最终状态。

#### 11. 时间轴不是可工作的编辑工具

**证据**：`components/video-studio.tsx:376-383` 每行只有 3px 高色条，只有点击色块才能 seek，没有刻度、播放头、拖拽、缩放和有意义的 tooltip；所有按钮的 `aria-label` 都只是“跳转到句子/镜头/配乐”。

**修复**：

- 轨道高度 16–24px，按钮命中区域至少 44px；短 cue 用透明 hit area 扩大可点范围。
- 加 0/25/50/75/100% 或每 5 秒刻度、当前播放头、当前时间 / 总时长。
- 支持点击空白 seek、拖拽播放头、左右方向键微调，Shift + 方向键大步调整。
- hover/focus tooltip 显示内容、起止时码、来源状态（精确/估算）。
- 每行使用 `role=group`，按钮名称包含编号和内容摘要。

**验收**：短句和短配乐在桌面、触屏和键盘下都能准确定位；播放头和 Remotion 当前帧误差不超过一帧。

### P2：提高布局密度和长稿效率

#### 12. 面板切换会改变左右栏比例，预览位置跳变

**证据**：`components/video-studio.tsx:339-360`：分镜、风格、角色使用 `420px + 内容`，其他面板使用 `内容 + 340–420px`；切换 tab 后左右列方向和预览宽度改变。

**问题**：用户调字幕、镜头和配音时视觉锚点不断移动，尤其预览中的当前时间和画幅会跳。

**布局建议**：桌面固定为 `预览轨 55% / 编辑轨 45%`，轨道之间提供可拖动 splitter，记住用户宽度。预览轨内部 sticky：播放器、时间轴和当前状态；编辑轨内部滚动，tabs 固定在编辑轨顶部。面板不再改变两列顺序。

**移动端建议**：顶部保留播放器和当前状态，编辑面板改为底部抽屉或全屏编辑页；抽屉打开时保留一个“回到预览”按钮和当前播放位置，不让用户在整页上下寻找播放器。

#### 13. 七个 tab 横向滚动，信息分类不够清晰

**证据**：`components/video-studio.tsx:348-350` 使用 `overflow-x-auto` 的按钮条，没有 `aria-controls`、`tabpanel`、方向键或 URL 状态；移动端需要横向扫动。

**修复**：将面板分成三组：`内容`（句子、角色、镜头）、`画面`（画面风格、字幕、配乐）、`输出`（设置、渲染版本）。桌面显示分组 tab，移动端用“当前面板 + 更多”菜单。实现 WAI-ARIA tabs：稳定的 tab/panel ID、roving tabindex、Home/End/Arrow、自动滚动当前 tab；面板写入 URL query（如 `?panel=storyboard`），刷新和返回仍保留上下文。

#### 14. 句子列表与分镜列表形成双重滚动

**证据**：`components/video-controls.tsx:532-553` 句子列表有 `max-h-[520px] overflow-y-auto`；页面右栏本身也随页面滚动。分镜在 `:749-757` 使用三列卡片，高级表单在 `:844` 展开后卡片高度剧烈变化。

**修复**：长句子改按段落折叠、虚拟化或分页；顶部固定搜索/当前句/缺失配音过滤。分镜默认两列宽卡或单列，卡片只保留预览、状态和关键动作；高级设置放右侧属性抽屉，避免瀑布流高度跳动。

#### 15. 错误和问题提示没有稳定的承载层

**证据**：`components/video-studio.tsx:269`、`components/video-controls.tsx:98,510`、分镜生成 `:646,670` 直接渲染普通文本；时间轴 issues 在 `video-studio.tsx:343` 逐条输出。

**修复**：统一三种承载：

- 动作失败：就近 toast，带“重试”。
- 任务失败：步骤卡/句子卡/镜头卡内联展示，带任务上下文和重试。
- 阻塞问题：顶部可聚焦 alert，带跳转和修复 CTA。

所有 `role=alert` 只在内容变化时播报一次；问题列表默认收起，显示数量和最高严重级别，展开后按“问题 → 修复动作”排列。

`blocked` / `waiting` 需要结构化为 `{ code, message, panel, action }`，例如“未配置文本模型 → 去模型中心”“曲库没有已核实音乐 → 去配乐”。纯文本不能让用户知道下一步。

#### 16. Worker 离线横幅面向开发者

**证据**：`components/job-strip.tsx:108-116` 直接显示 `npm run worker` 和 `npm run dev:all`。

**问题**：普通用户无法执行命令，提示占据页面高度却没有刷新/重试动作。

**修复**：默认显示“生成服务暂时离线，任务已保留；恢复后会自动继续”，附“重新检查”与“查看详情”。命令放进开发模式诊断抽屉，生产环境不展示。

#### 17. 成片区只是下载列表，不支持交付检查

**证据**：`components/video-studio.tsx:394-395` 只有 MP4/SRT 链接和新旧徽章。

**修复**：每个版本增加缩略图、播放、下载、复制链接、删除/保留策略和“按当前设置重新生成”。支持按 `画幅 / 样片·成片 / 当前·过期` 筛选；过期版本保留下载能力，但明确“不代表当前设置”。

## 动效与状态反馈规范

动效只用于解释状态变化，统一时长和语义：

| 场景 | 动效 | 时长 | 备注 |
|---|---|---:|---|
| 保存成功 | 状态文字从“保存中”过渡为“已保存”，勾选淡入 | 180–220ms | 不弹 toast 打断编辑 |
| 任务开始 | 进度条从 0 到当前值，步骤边框一次强调 | 160–400ms | 不无限闪烁 |
| 任务完成 | 进度条完成 + 勾选 | 220ms | 保持静态结果 |
| 任务失败 | 红色边框/图标淡入，操作按钮出现 | 180ms | 不抖动，不自动滚动 |
| 预览更新 | 半透明状态层 + 完成后淡出 | 160ms | 保留播放位置 |
| 当前句/镜头 | 背景或边框轻量高亮 | 120ms | 播放时跟随，暂停时保持 |
| 画幅切换 | skeleton 保持目标比例，旧画面淡出 | 160–240ms | 不从横屏闪到竖屏 |
| 成片就绪 | 缩略图淡入、状态变为“最新” | 240ms | 不自动播放声音 |

全局补充：`prefers-reduced-motion: reduce` 时去掉 pulse、scale 和位移，只保留颜色/文本状态；所有进度仍必须有数字和文案，不能只靠颜色或动画。

## 推荐信息架构

桌面工作区建议固定为三层：

1. **顶部动作条**：项目名、保存/实时连接、设置快照状态、总体进度、停止/生成主动作。
2. **左侧预览轨**：播放器、当前句/镜头、可拖动时间轴、问题摘要。
3. **右侧编辑轨**：分组 tabs、固定 tab header、当前面板内容、面板级保存/失败状态。

移动端建议采用两态：

- **预览态**：播放器 + 当前阶段 + 时间轴 + 主动作。
- **编辑态**：全屏或底部抽屉编辑，顶部显示“返回预览”和当前面板名。

“生成成片”和“生成样片”应始终在同一动作区，并显示当前画幅、费用、预计步骤数；停止按钮只在有活动任务时出现，停止后保留“已完成结果”和“继续制作”。

## 可直接分派的 Agent 工作包

### Agent A：保存、确认和实时连接可靠性（P0）

**文件**：`components/video-studio.tsx`、`components/project-bar.tsx`、`lib/client.ts`、必要的 `components/studio-status-bar.tsx` 测试。

实现设置快照确认、等待保存后路由、SSE 重连状态、刷新 request token/trailing refresh。增加延迟请求、断线、改设置后确认失效和保存冲突测试。

### Agent B：任务状态条和批次反馈（P0/P1）

**文件**：`components/job-strip.tsx`、`components/video-controls.tsx` 的批次状态区域、`components/studio-status-bar.tsx`。

实现取消/重试中间态、`Promise.allSettled` 汇总、提交后任务登记状态、总体进度/ETA/可展开详情。确保每个长任务都有停止入口和失败补救。

### Agent C：预览与时间轴交互（P1）

**文件**：`components/video-preview.tsx`、`components/video-studio.tsx` 的 `TimelineStrip`，独立 timeline interaction tests。

实现比例稳定 skeleton、播放头、刻度、拖拽 seek、tooltip、键盘微调、当前句/镜头高亮、预览错误与更新状态。不要同时改右侧面板布局。

### Agent D：制作工作区布局和 tabs（P2）

**文件**：`components/video-studio.tsx`、必要的 `components/ui.tsx`、`app/globals.css`。

固定桌面左右轨道，增加 splitter 或稳定宽度；移动端改预览/编辑两态；实现 WAI-ARIA tabs 和 URL 面板状态。与 Agent C 协调，避免同时修改 `video-studio.tsx` 的时间轴区域。

### Agent E：长稿和成片交付效率（P2）

**文件**：`components/video-controls.tsx`、`components/video-studio.tsx` 的 `RenderList`、必要的媒体预览组件。

实现句子过滤/按段折叠、分镜属性抽屉、成片预览与按画幅筛选/重新生成、镜头候选图可访问名称和 retry busy。先由 Agent B 固定任务状态契约。

### Agent F：视觉状态规范与无障碍收口（P3）

**文件**：`app/globals.css`、`components/ui.tsx`、制作页相关组件测试。

统一 reduced-motion、role=alert、progressbar、tab/tabpanel、disabled 样式、焦点管理和动效时长。检查窄屏、键盘和屏幕阅读器路径。

## 总体验收清单

- [ ] 改音色/预算/画幅/素材策略后，旧的开工确认自动失效。
- [ ] 延迟保存时切换文案/制作页面不会丢最后编辑。
- [ ] SSE 断开、恢复、刷新失败、旧响应覆盖新响应都有可见状态。
- [ ] 取消和重试有 pending、部分成功和错误反馈，不会重复提交。
- [ ] 每个长任务显示已完成/总数、阶段、ETA、停止入口和继续语义。
- [ ] 横屏/竖屏切换不发生骨架比例跳变，预览更新保留播放位置。
- [ ] 时间轴支持鼠标、触摸、键盘定位，并显示播放头和内容 tooltip。
- [ ] 桌面切换面板时预览列不跳变；移动端可以在预览和编辑之间快速切换。
- [ ] tabs 满足 `tab` / `tabpanel` 语义，刷新和返回保留当前面板。
- [ ] 长稿没有页面与面板双滚动陷阱；长分镜高级设置不再撑乱瀑布布局。
- [ ] 成片可预览、筛选、按画幅重新生成和下载；过期状态说明具体原因。
- [ ] `prefers-reduced-motion`、键盘操作、焦点可见性和 `role=alert/progressbar` 检查通过。
- [ ] 运行 `npm run typecheck`、`npm run lint`、相关 Vitest、`npm run build`，并确认 `/changelog` 页面仍从 `lib/changelog.ts` 正常渲染。
