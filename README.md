# DO·Vedio — AI 视频文案工坊

输入视频标题、内容概要和目标时长，选择一种解说风格，由大模型自动生成**带分段时间轴**的 B站/西瓜视频口播文案。

> **范围说明**：本 README 只讲**怎么安装、怎么配模型、文案功能怎么用**。项目架构、目录职责、以及「要改 X 该看哪个文件」，都在 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)——**两者冲突时以架构地图为准**。本仓库已从文案工坊长成完整的视频生产流水线，下面「功能」一节只覆盖其中的文案环节。

## 功能

- **按时长控字数**：舒缓 / 适中 / 紧凑三档语速（200 / 250 / 300 字每分钟）。时间轴按实际字数计算，不采用模型自己估的时长
- **概要可留空**：AI 按所选风格的「选题偏好」构思 3 个切入角度（含开场钩子、要点、内容性质），选中后自动写入概要；支持「换一批」。概要为空时点「一键成稿」，会自动采用第一个角度
- **防编造**：每个角度标注「真实科普 / 观点评论 / 虚构故事」，写稿时按性质约束；全局要求不编造具体数据、人名和出处
- **两步生成**：先生成大纲，可增删章节、调整每章时长；再逐章流式写稿，章与章之间自动衔接
- **8 种内置风格**：严肃权威、幽默风趣、犀利吐槽、悬疑叙事、知识科普、温情治愈、热血激昂、纪录片旁白
- **自定义风格**：可以手动创建（含选题偏好）；也可以粘贴自己以前的文案，让 AI 提炼出风格模板和选题习惯
- **分段改写**：扩写、缩写、更口语化、换风格、自定义要求、校准到目标字数，另有去 AI 味、加点梗、去掉梗（见下），每段都能撤销一次
- **热梗与网感**：轻松类视频可以用上近期流行的梗，严肃类默认不用
  - 梗库（导航「梗库」）：用通义千问联网搜索近 30 天 B站、抖音、微博、小红书上的流行梗，整理出含义、用法、平台、流行时间、热度和风险。没写流行时间或平台的条目直接丢弃；超过 60 天没被再次搜到的自动视为退潮
  - 网感档位：关 / 点缀 / 适中 / 浓，默认跟随风格（幽默、吐槽适中；科普、温情、热血点缀；严肃、纪录片、悬疑关）。选题角度提示题材沉重时自动关闭
  - 先挑再写：网感开启时，生成前从梗库里挑出和这期搭得上的梗，勾选后才开始写；也可以「按本期题材再搜一轮」。文案只用勾选的梗，不用列表外的网络流行语，按字数控制用量，同一个梗全片最多两次，不解释梗
  - 按章节分配：出大纲时把梗分到最搭的章节（每章 0-2 个，不重复、不超量），大纲编辑器里可以增删；写稿时每章只用分到的梗
  - 分段改写多了「加点梗」「去掉梗」
  - 梗库超过 7 天没刷新时，挑梗会在后台自动刷新；也可以手动添加一个梗（联网核实含义和热度）或粘贴一段文字导入
  - 刷新时把近 30 天确认过的梗告诉模型不用再列，名额留给新梗（更早的仍可能再次搜到并续期）；可以按圈层刷新（职场、情感、游戏、二次元等），每个梗也会归到一个圈层，梗库里可按圈层筛选
  - 本次新增的梗标「新」并排在前面；删除时可选「不再收录」，以后刷新搜到它的任何写法都跳过，可在页面底部「已屏蔽」里恢复
  - 逐个核实：刷新时改为摘录「热梗盘点」类文章和热词榜里点名的梗；每个新梗入库前再单独联网搜一次这个词，多个独立来源、有原句的才算「已核实」，完全查不到的直接丢弃，来源不足的标「待核实」不进候选。「核实现有梗」对没核实过和超过 30 天没确认的梗做同样的核实，并更新热度和流行时间；每次刷新也会顺带复核最旧的 5 个
  - 粘贴导入：把「热梗盘点」文章、评论区或弹幕贴进来，AI 抽出梗后先给预览，勾选并改好才入库。每个梗都必须真的出现在原文里（模型顺手编的直接丢弃），原文摘录由程序从原文截取；原文没解释含义的标「含义为推测」；能看出发布时间时会给出发旧提醒；可联网核实热度（只更新热度和流行时间）。这是目前拿到真梗最可靠的方式
  - 搜索时间窗口可选近 1 个月、近 3 个月、近半年；流行时间统一成「年-月」，梗库可按流行时间（近 3 个月、半年、一年、更早）、可信度筛选，支持搜索和排序
  - 和去 AI 味、配音衔接：去 AI 味新增第 12 条规则「硬凹网感」，查过气梗（yyds、绝绝子、家人们谁懂啊，以及梗库里标为过气的）、超出档位的用量和解释梗的句子；清理时保留选用的梗（删了就不采用结果）；梗的读法（如 yyds → 永远的神）自动并入读音词典
  - 需要配置 `DASHSCOPE_API_KEY`；一次联网刷新大约需要三到五分钟（每个新梗都要单独再搜一遍核实）
- **时长校准**：总时长偏差超过 ±15% 时给出提示，一键把偏差大的段落改写到目标长度
- **去 AI 味**：规则移植自 [lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone)（基于 283 万字人类 / AI 对照语料实测的 11 条规则），另加 1 条自研的「硬凹网感」，共 12 条，分三层接入：
  - 预防：所有生成环节的提示词都带上 AI 高频写法清单（翻案腔、破折号揭晓、提示性冒号、翻译腔等），同时列出实测**不是** AI 痕迹的写法（设问、比喻、句内排比），防止矫枉过正
  - 检测：每段显示「AI 味 N」，点开可看命中的规则、原文片段和改法；按触发标记检测，只代表“疑似”
  - 改写：白名单式最小改动，只改命中规则的句子，信息不增不删。成稿后可自动处理（表单里的开关），也可以逐段或一键全文处理。结果要过验收（段落数、字数漂移、没有凭空多出的句子、疑似命中不增加），不通过就保留原文。未改动的句子逐字不变，视频制作里的配音缓存和镜头锚点不受影响
  - 风格模板优先：模板的推荐写法与规则冲突时以模板为准；从样本提炼风格时，会把作者本来就爱用的破折号、冒号等习惯记进模板
- **发布素材**：生成 3 个备选标题、带章节时间戳的简介和 10 个标签
- **自动保存到服务端**：稿件实时存入项目库（节流提交 + 版本号，防并发覆盖），刷新页面不丢，换浏览器或换设备也在；与制作环节自动写回的内容冲突时会先尝试自动合并，合并不了才让你选。支持复制全文和导出 Markdown

## 快速开始

需要 Node.js 22.13 或更高版本（23.4+ / 24+ 亦可）。项目用到 `node:sqlite`，22.0–22.12 会被拒绝启动。

```bash
npm install
cp .env.local.example .env.local   # 至少填一个 API Key
# 背景音乐放到 bgm/（mp3、m4a、wav、aac、ogg、flac、opus）。启动后自动扫描，在制作页选一首即可。
```

之后**双击根目录的「启动.bat」**即可：网页和 Worker 一起在后台拉起，然后用浏览器访问 http://localhost:3000（不会自动打开浏览器）。
已经在跑的时候再双击一次就是重启（旧的自动收掉），不用先手动关。

命令行下同样一个入口（`%*` 参数会传给 `scripts/start.mjs`）：

```bash
启动.bat                # 启动 / 重启（后台，日志写 logs/）
启动.bat status         # 看是否在运行、PID 与日志位置
启动.bat stop           # 停止网页与 Worker
启动.bat --fg           # 前台运行，日志直接打到终端（Ctrl+C 一起停）
```

不用 bat 时：`npm run up`、`npm run up -- stop`、`npm run up -- status`。
想看后台输出：`Get-Content logs\web.log -Wait`（macOS/Linux：`tail -f logs/web.log`）。

内网部署（先 `npm run build`）：

```bash
# .env.local 中配置访问令牌；需要局域网访问时再明确打开监听地址
DO_VEDIO_ACCESS_TOKEN=请替换为随机长令牌
DO_VEDIO_HOST=0.0.0.0
启动.bat --prod         # next start + worker，后台运行
```

生产模式默认只监听 `127.0.0.1`（由 `启动.bat --prod` / `scripts/next-start.mjs` 收紧），不会因为启动 `next start` 而自动暴露到局域网；只有显式设置 `DO_VEDIO_HOST=0.0.0.0` 才开放局域网访问。

**生产模式缺少令牌会直接返回 503，与监听地址无关**——即使只监听 `127.0.0.1` 也一律拒绝请求，所以「开放局域网」之前必须先配好 `DO_VEDIO_ACCESS_TOKEN`。配置令牌后，页面会先跳转到 `/login`，所有 `/api` 请求也会校验 HttpOnly Cookie。

开发模式没有这层保护：未配置令牌时不鉴权，而且 `next dev` 自身的默认监听地址不是 `127.0.0.1`。要限制监听范围请用 `--prod`。

## 模型配置

在 `.env.local` 中配置 Key。**只有配置了 Key 的模型才会出现在页面上**。

| 服务商 | Key | 默认模型 | 覆盖模型名 |
|---|---|---|---|
| DeepSeek | `DEEPSEEK_API_KEY` | deepseek-chat | `DEEPSEEK_MODEL` |
| 通义千问 | `DASHSCOPE_API_KEY` | qwen-plus | `QWEN_MODEL` |
| Kimi | `MOONSHOT_API_KEY` | kimi-latest | `KIMI_MODEL` |
| 豆包 | `ARK_API_KEY` | doubao-seed-1-6-250615 | `DOUBAO_MODEL` |
| OpenAI | `OPENAI_API_KEY` | gpt-5 | `OPENAI_MODEL` |
| Claude | `ANTHROPIC_API_KEY` | claude-opus-5 | `ANTHROPIC_MODEL` |

每个服务商的接口地址都可以用 `<ID>_BASE_URL` 覆盖（例如 `DEEPSEEK_BASE_URL`），用于接入代理或私有部署。Claude 默认开启服务端 `fallbacks: "default"`：请求被安全分类器拦截时，会自动改用推荐的后备模型重试。

### 添加第三方服务商

打开「模型中心」，填写服务商名称、接口协议（OpenAI Compatible 或 Anthropic Messages）、Base URL 和 API Key，点击「添加服务商」。服务端会自动尝试 `/v1/models`（Base URL 填根地址时再补试 `/models`）；OpenAI Compatible 通常填写到 `/v1`，Anthropic 通常填写服务商根地址或 `/v1`。模型同步成功后默认停用；启用模型后，它会出现在创作页模型选择器中。

自定义服务商的 API Key 使用 `PROVIDER_ENCRYPTION_KEY` 加密保存，不会返回到浏览器。部署前请在 `.env.local` 配置一个稳定的密钥，例如：

```bash
openssl rand -hex 32
```

将输出填入 `PROVIDER_ENCRYPTION_KEY`，之后重启网页和 Worker。更换该密钥会导致已保存的自定义服务商 Key 无法解密，需要重新添加。

## 目录

完整的分层、目录职责与「要改哪里 → 去哪儿找」路由表见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。这里只给一层概览：

```
app/              路由：首页 / 项目 / 爆款复创 / 梗库 / 动画库 / 解说风格 / 画面风格 / 设置 / 更新记录 / 登录，以及 api/ 下 81 个接口
components/       UI。顶层是创作台与制作页外壳；studio/ 制作页各面板；viral/ 复创工作台
lib/core/         纯领域层（无 I/O）：文档类型、时间轴、分镜、角色、字幕、运镜、缓存键
lib/pipeline/     任务编排：stage 契约、调度计划、14 个步骤——Worker 的心脏
lib/server/       持久化与外部资源：SQLite、迁移、任务队列、媒体、缓存、ffmpeg、存储清理
lib/providers/    模型服务商接入；media/ 图片视频生成；tts/ 语音合成适配
lib/viral/        爆款复创领域逻辑；humanize/ 去 AI 味；aix/ 风格库适配；templates/ 风格模板
lib/*.ts          散件：prompts（各环节提示词）、llm（多模型接入）、memes（热梗规则）、
                  duration（字数/时长换算）、client（前端 hooks）、changelog（更新记录数据）
remotion/         视频合成：layers / shots / animation
worker/           Worker 进程：轮询任务表、执行步骤、定时存储维护
proxy.ts          访问令牌鉴权（Next.js 16 的中间件入口，配合 lib/auth.ts）
scripts/          启动脚本与调试探针（tts-probe、animation-probe 等）
docs/             ARCHITECTURE.md 是唯一上手读物；archive/ 是已实现的历史计划，不要通读
```

**「web + worker 双进程」是理解本项目的关键**：网页只写任务表，重活由 Worker 领取执行。详见架构地图第二节。
